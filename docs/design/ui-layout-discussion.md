# Home Center UI 布局讨论稿

## 目标

本文用于先讨论 Home Center 后续 UI 大概做成什么样，再进入页面调整和实现。它不是最终视觉稿，也不是接口实现文档。

本阶段目标：

- 明确整体 UI 信息架构。
- 明确公开首页、登录页、私有导航、后台管理、设备控制几类页面的布局方向。
- 保持公开入口和私有入口边界清晰。
- 保持现有技术边界：原生 HTML、CSS、JavaScript，优先复用 `app-theme.css`、`app-theme.js` 和 `window.HomeCenter`。
- 为后续逐页改造提供可检查的布局依据。

## 基础判断

Home Center 的 UI 不应该做成单一风格的“后台系统”，也不应该做成纯展示型官网。它需要同时承载三类体验：

1. 公开入口：访客能快速看到公开导航和公开应用入口。
2. 登录后个人工作台：用户快速进入自己的私有导航、设备、管理入口。
3. 后台管理工具：超管高效维护用户、权限、导航、设备、审计和配置。

因此整体布局建议采用“同一视觉语言，不同页面密度”的方式：

- 公开首页：轻量、干净、移动端可用。
- 登录页：聚焦、可信、少干扰。
- 私有导航：像个人工作台，强调搜索、分组、常用入口和状态。
- 后台管理：桌面端工具布局，侧边栏加内容表格。
- 设备控制：状态优先，危险操作克制，控制区清晰隔离。

## 全站布局骨架

全站保持一致的基础骨架：

```text
页面背景
└── 顶部区域
    ├── 左侧：Home Center / 当前模块 / 返回入口
    ├── 中间：必要时显示模块导航或上下文
    └── 右侧：主题切换 / 用户入口 / 登录或退出
└── 主内容区域
└── 底部区域
```

### 顶部区域

建议后续统一为两种形态：

- 公开和普通页面：简洁顶栏，高度约 `56px`，适配手机端。
- 后台管理页面：桌面工具顶栏，高度约 `56px` 或 `64px`，和左侧菜单配合。

顶部区域只承担系统级导航和页面上下文，不在多个位置重复放同级导航。

已确认通用规则：

- 大部分页面顶部都需要显示 `Home Center` 或当前模块标识。
- 所有页面都需要提供明暗主题切换按钮。
- 主题切换按钮做成全局统一组件，不允许每个页面单独设计一套。
- 主题切换按钮默认放在页面右上角，作为通用页面操作区的一部分。

### 底部区域

底部只放低频信息，例如版本、运行环境、版权或简单状态。公开首页可以保留轻量底部；后台管理页面可弱化或不突出底部。

已确认通用规则：

- 公开首页、登录页、内部私有导航页需要统一的简洁页脚。
- 页脚默认文案为 `© Home Center | By wwh`。
- 页脚视觉要很克制、不显眼，只承载低频信息。
- 页脚不放主要操作按钮，不承担主要导航。

## 页面分区方案

### 1. 公开首页

定位：公网默认入口，面向未登录用户和已登录用户都可访问。

已确认方向：

- 公开首页采用“个人门户首页”形态。
- 顶部显示 `Home Center` 标识，作为大部分页面共用的全局头部元素。
- `Home Center` 标识旁边或下方保留一句很简短的说明，默认文案为“个人服务入口”。
- 主内容包含搜索、分组和导航入口。
- 右上角显示主题切换按钮和“后台登录”入口。
- 点击登录入口进入登录页。
- 登录页需要提供返回公开首页的功能。
- 登录成功后进入登录用户的内部私有导航页。

建议布局：

```text
顶部栏
├── Home Center
├── 搜索入口或简短说明
└── 登录 / 用户入口 / 主题切换

主区域
├── 搜索框
├── 公开导航分组
│   ├── 分组标题
│   └── 入口卡片网格
└── 空状态 / 加载失败状态

底部
└── 低频系统信息
```

布局重点：

- 首页第一屏直接显示搜索和公开导航，不做大面积营销 hero。
- 搜索框采用普通工具栏式，视觉克制，不做居中大搜索入口。
- 导航分组采用“分组标题 + 卡片网格”布局。
- 导航卡片采用相对舒展的门户入口样式，图标更明显，卡片高度更宽松，但整体仍保持简洁。
- 导航卡片默认只展示图标和名称。
- 导航描述默认不直接占用卡片空间，鼠标悬停时展示描述信息。
- 移动端没有悬停能力时，描述不作为主要信息；必要时可通过点击详情或长按提示等后续交互补充。
- 公开导航 URL 类入口点击后默认在新窗口或新标签页打开。
- 公开首页内容区先采用中等宽度布局，避免桌面端卡片铺得过散。
- 公开首页背景可以使用动画纹理效果或科技感粒子效果，增强门户识别度。
- 背景方向确定为“科技感粒子 + 克制密度”。
- 公开首页、登录页、内部私有导航页使用相同的粒子背景效果，形成统一入口体验。
- 粒子背景后续实现时需要抽取为公共能力，例如公共 CSS/JS 或统一背景组件，不能在三个页面重复复制实现。
- 动态背景必须克制，不能影响导航卡片、搜索框和顶部操作的可读性。
- 移动端或低性能设备需要提供降级方案，例如降低粒子数量、暂停动画或使用静态背景。
- 公开首页顶部栏采用半透明毛玻璃样式，配合轻边框，保证粒子背景下仍然清晰可读。
- 公开首页主内容使用一个较稳定的半透明大面板承载搜索、分组标题和导航卡片，避免粒子背景让内容显得零散。
- 大面板内的导航卡片不再使用强毛玻璃效果，避免玻璃层级过多；卡片使用轻量半透明块、轻边框和 hover 高亮。
- 导航卡片图标使用圆角方形容器，强化工具门户感，并便于和后台、设备入口保持统一。
- 公开首页不显示时间、日期、天气等附加信息，保持页面聚焦搜索和公开入口。
- 公开首页不展示健康检查状态。
- 移动端优先保证搜索框、卡片网格和登录入口可用。
- 未上传图标时使用稳定占位图标，避免卡片错位。

待讨论点：

- 是否在公开首页顶部显示一句简短说明，例如“个人服务入口”。
- 公开导航是否需要“常用 / 工具 / 应用”这种固定分区，还是完全由后台分组决定。
- 已登录用户访问公开首页时，顶部是否显示“进入私有导航”快捷入口。

### 2. 登录页

定位：统一登录入口，支持直接登录和从 nginx / SSO 回跳场景进入。

已确认方向：

- 登录页和公开首页、内部私有导航页共用“科技感粒子 + 克制密度”的背景效果。
- 登录页保留和公开首页一致的顶部栏。
- 顶部栏显示 `Home Center` 和“个人服务入口”短说明。
- 右上角保留全局统一的主题切换按钮。
- 底部使用统一简洁页脚：`© Home Center | By wwh`。
- 登录面板放在页面视觉中心略微偏上的位置，不做机械垂直居中。
- 登录面板采用半透明毛玻璃样式，但透明度比公开首页主面板更低，保证表单输入和错误提示清晰可读。
- 登录面板标题使用“登录 Home Center”。
- 登录面板不放副标题说明，保持登录动作直接。
- “返回首页”放在登录面板底部，作为低强调文字链接。
- 登录主按钮文案使用“登录”。
- 登录错误提示分层处理：字段校验错误显示在对应字段下方；账号密码错误、会话失效等整体错误显示在表单顶部。
- 密码框提供显示/隐藏密码按钮，使用低强调图标按钮，不抢主操作。
- 登录页不提供“记住我”，避免和短期会话、12 小时硬上限策略冲突。
- 登录成功跳转规则：如果存在合法返回目标，优先回到目标地址；否则进入内部私有导航页。

建议布局：

```text
居中登录面板
├── Home Center 标识
├── 登录说明
├── 用户名
├── 密码
├── 登录按钮
└── 错误提示 / 返回首页
```

布局重点：

- 手机端和桌面端都居中显示。
- 不放无后端支撑的注册、找回密码等伪功能。
- 登录失败在表单附近明确提示。
- 登录成功后的跳转目标要稳定：优先返回原始目标地址，否则进入私有导航。
- 如果来自代理系统或自研应用，页面可显示低调的“登录后返回目标页面”提示，但不暴露真实内部地址细节。

待讨论点：

- 登录页是否保留背景动效。建议控制强度，不能影响加载和可读性。
- 是否展示当前将要返回的应用名称。第一版可以只展示通用提示，不解析具体应用。

### 3. 私有导航页

定位：登录后的个人入口集合，不等同于后台管理。

已确认方向：

- 内部私有导航页和公开首页、登录页共用“科技感粒子 + 克制密度”的背景效果。
- 顶部栏沿用半透明毛玻璃样式。
- 主内容使用一个半透明大面板承载搜索、分组和私有导航卡片。
- 底部使用统一简洁页脚：`© Home Center | By wwh`。
- 私有导航页属于登录后的个人入口工作台，不等同于后台管理。
- 顶部标识显示 `Home Center`，短说明使用“内部导航”。
- 顶部右侧不是固定写死的几个入口，而是由登录用户角色和权限加载的菜单区。
- 菜单需要支持下拉，一个用户可能看到多个系统级菜单；“后台管理”只是其中一个有权限才显示的菜单。
- 用户区显示头像、姓名或昵称，点击后展开用户菜单，包含维护/更新个人信息、退出登录等功能。
- 主题切换是所有用户都有的全局能力，但视觉上应放在最不起眼的位置，作为低强调工具按钮。
- 私有导航顶部右侧顺序为：权限菜单区、用户头像姓名菜单、低强调主题切换按钮。
- 私有导航搜索框视觉上和公开首页一致，采用普通工具栏式、克制样式。
- 私有导航卡片默认展示图标、名称、入口类型小标识和轻量健康状态点。
- 入口类型标识使用短文案，第一版包括“代理”“外链”“内网”“命令”。
- 私有导航描述信息仍然默认隐藏，鼠标悬停时展示。
- 私有导航点击行为需要支持可配置的展示形态，不应只由入口类型硬编码决定。
- 第一版至少保留三种点击展示形态：直接新标签页打开、说明/命令小弹框、公网访问地址/内网访问地址选择弹框。
- 说明/命令类入口点击后可打开小弹框，展示说明或命令内容，并提供复制和关闭操作。
- 已有系统中的“公网访问地址 | 内网访问地址”选择弹框需要继续支持，适合同时配置公网和内网地址的入口。
- 私有导航前台先聚焦使用入口，不放明显的“新增入口”按钮；入口维护放到配置或管理界面中完成。
- 私有导航暂不设置单独的“常用入口”置顶区域，先按分组和排序展示。
- 私有导航分组布局和公开首页一致，采用“分组标题 + 卡片网格”。
- 私有导航卡片尺寸和公开首页保持一致，采用舒展门户入口样式。
- 私有导航健康状态点放在卡片右上角，以小圆点或轻量 badge 表示，不展示详细错误。
- 私有导航空状态显示“暂无内部导航入口”，并提示到配置界面维护私有导航。
- 如果当前用户有对应配置权限，空状态可提供低强调“去配置”按钮；没有权限时只显示提示。

建议布局：

```text
顶部栏
├── Home Center / 私有导航
├── 搜索
└── 权限菜单 / 用户头像姓名 / 低强调主题切换

主区域
├── 常用入口
├── 分组导航
│   ├── 分组标题 + 数量
│   └── 入口卡片网格
└── 说明类入口弹窗
```

入口卡片建议信息：

- 图标。
- 名称。
- 简短描述或目标类型。
- 入口类型 badge：代理、外链、内网、命令。
- 轻量健康状态：小圆点或短 badge，仅私有导航展示。

交互规则：

- URL 类入口默认新窗口打开。
- SSH/RDP/命令说明类入口点击后弹窗展示说明和复制按钮，不直接跳转。
- 健康异常不阻止点击。
- 搜索应覆盖名称、描述、分组和入口类型。
- 用户只能看到自己的私有导航数据。

待讨论点：

- 是否需要“常用入口”置顶。可以先按排序或后台标记支持，后续再做。
- 私有导航是否允许用户在前台直接新增和编辑入口，还是第一版只在后台管理。
- 健康状态在卡片上显示圆点还是文字 badge。

### 4. 后台管理

定位：桌面端管理工具，服务超管和有权限用户。

已确认方向：

- 后台管理不沿用公开首页、登录页、内部导航页的粒子背景，避免影响管理效率。
- 后台管理采用桌面端工具布局：左侧固定菜单、顶部工具栏、右侧内容区。
- 后台模块会持续增长，长期使用左侧菜单比顶部 tab 更稳定。
- 后台管理跟随全局明暗主题，默认优先按浅色管理台优化，同时保证深色模式下表格、表单和弹窗可读。
- 后台左侧菜单使用固定宽度展开态，并支持折叠成窄栏。
- 后台菜单展开态显示图标和文字；折叠态只显示图标，并通过 hover tooltip 提供完整菜单名称。
- 后台左侧菜单需要分组展示，降低模块增多后的扫描成本。
- 后台顶部工具栏左侧显示当前模块标题或面包屑，右侧显示用户菜单和低强调主题切换。
- 后台顶部工具栏不重复放模块入口，模块入口统一由左侧菜单承载。
- 后台内容区占满左侧菜单之外的剩余宽度，整体按桌面端管理工具设计。
- 后台页面推荐最小宽度约 `1180px`，不做移动端适配。
- 表格列过多时在内容区内部横向滚动，不撑破整体页面。
- 后台列表页统一采用“页面标题区、工具栏、筛选区、表格、分页”的结构。
- 后台新增和编辑默认使用弹窗；字段较多或配置复杂时使用抽屉或独立页面。
- 后台需要一个简单概览首页，展示用户、在线会话、设备在线、最近审计、系统状态等摘要。
- 后台概览第一版不做复杂图表，以摘要卡片和简短列表为主。
- 后台第一版菜单分组方向：概览、用户与权限、导航管理、设备、应用接入、系统。

建议布局：

```text
后台外壳
├── 左侧菜单
│   ├── 概览
│   ├── 用户与权限
│   ├── 公开导航
│   ├── 私有导航
│   ├── 设备管理
│   ├── SSO 应用
│   ├── 审计日志
│   └── 系统配置
├── 顶部工具栏
│   ├── 当前模块标题 / 面包屑
│   └── 用户菜单 / 主题切换
└── 内容区
    ├── 工具栏
    ├── 筛选区
    ├── 表格
    └── 分页 / 弹窗
```

布局重点：

- 后台按桌面端设计，推荐最小宽度 `1180px`。
- 左侧菜单只展示当前用户有权限访问的模块。
- 内容区以表格、筛选、弹窗表单为主。
- 危险操作，如删除、踢出会话、禁用设备、关机重启，必须二次确认。
- 表格列过多时允许内容区横向滚动，不把页面整体撑坏。

后台模块建议：

- 概览：系统状态、设备在线概况、近期审计摘要。
- 用户管理：用户、角色、权限、启用禁用。
- 导航管理：公开导航和私有导航分开管理。
- 设备管理：设备列表、在线状态、基础操作。
- 会话管理：在线会话、踢出、过期信息。
- SSO 应用：应用接入、授权范围、密钥管理。
- 审计日志：登录、SSO、设备操作、命令执行。
- 系统配置：非敏感配置项。

待讨论点：

- 后台是否采用固定左侧菜单，还是顶部 tab。建议固定左侧菜单，更适合模块增长。
- 私有导航后台是否允许超管查看或维护其他用户的私有入口。当前需要单独确认，不能默认混入普通用户接口。
- 概览页第一版是否需要做，还是直接从具体管理模块开始。

### 5. 设备控制页

定位：查看设备状态，并对 PC Agent 设备执行受控操作。

建议按“后台工具页 + 控制台局部体验”处理。设备控制页不使用公开首页那套粒子背景，默认放在后台管理或登录后的受控区域内。页面重点不是展示效果，而是让用户明确知道当前控制的是哪台设备、设备是否在线、操作是否执行中、危险操作会造成什么影响。

建议布局：

```text
设备页面
├── 设备列表 / 设备选择
├── 当前设备状态栏
│   ├── 在线状态
│   ├── 最近心跳
│   ├── Agent 版本
│   └── 当前执行状态
├── 主要内容区
│   ├── 截图预览
│   ├── 状态详情
│   └── 操作记录
└── 操作区
    ├── 刷新状态
    ├── 获取截图
    ├── 进入 Web Shell
    ├── 重启
    └── 关机
```

布局重点：

- 状态优先，用户先知道设备是否在线、是否可操作。
- 离线、超时、执行中、失败、成功状态必须明确。
- 截图和 Web Shell 属于敏感能力，必须在登录后区域并经过权限控制。
- 关机和重启必须二次确认。
- Web Shell 进入前做风险确认，进入后单条命令不重复二次确认，但必须审计。

待讨论点：

- 设备控制放在后台内，还是作为登录后的独立页面。建议第一版放后台或私有区域，不暴露到公开入口。
- 截图预览是嵌在页面内，还是点击后弹窗大图。建议两者都支持：页面显示缩略，弹窗查看详情。

第一版建议：

- 设备列表采用表格或紧凑卡片列表，优先展示名称、在线状态、最近心跳、Agent 版本、可用操作。
- 设备详情页顶部固定显示目标设备名称和在线状态，避免误操作设备。
- 截图区域使用稳定比例容器，加载中、失败、超时、无截图都要有状态。
- Web Shell 使用独立页面或大弹窗，进入前显示风险确认；进入后顶部持续显示目标设备。
- 关机、重启放在危险操作区，使用二次确认，不和普通刷新、查看状态按钮混在一起。
- 操作结果要在页面内可见，不能只依赖 toast。

### 6. 用户资料页

定位：登录用户维护自己的基础资料和安全相关信息。

建议布局：

```text
用户资料
├── 基础信息
│   ├── 头像
│   ├── 昵称
│   └── 用户名只读
├── 安全设置
│   └── 修改密码
└── 最近登录/会话提示
```

布局重点：

- 用户资料可以从右上角用户菜单进入。
- 页面应保持简单，不做复杂个人中心。
- 用户名、角色、权限等系统字段默认只读。
- 修改密码属于安全操作，成功后按会话策略处理，必要时要求重新登录。
- 头像上传复用项目已有上传规则，不暴露真实文件路径。

### 7. 配置和维护页面

定位：维护导航入口、点击展示形态、图标、公网/内网地址、SSO 应用、系统配置等。

建议布局：

```text
配置页面
├── 标题区
├── 筛选/搜索
├── 表格
├── 新增/编辑弹窗或抽屉
└── 危险操作确认
```

布局重点：

- 配置类页面默认沿用后台列表页模板。
- 私有导航配置需要支持入口点击展示形态：直接新标签页、说明/命令小弹框、公网/内网地址选择弹框。
- 导航图标上传、预览、替换、删除放在新增/编辑表单内。
- 公网访问地址和内网访问地址都只能记录占位或配置值，不应在公开文档中出现真实敏感部署信息。
- 表单字段较多时使用抽屉，减少弹窗高度溢出。

### 8. 错误和会话失效页

定位：处理未登录、权限不足、会话过期、被踢出、系统错误等异常状态。

建议布局：

```text
状态页面
├── 简短标题
├── 可行动说明
└── 操作按钮
    ├── 返回首页
    ├── 重新登录
    └── 返回上一页
```

布局重点：

- 错误页文案要说明下一步，不只显示“失败”。
- 未登录或会话失效优先引导重新登录。
- 权限不足说明当前账号无权访问，不暴露内部权限细节。
- 普通用户可见错误页可以沿用入口页的简洁风格；后台内部错误状态可在内容区内显示，不必跳整页。
- 全局会话失效提示应统一，不在每个页面重复实现。

## 视觉方向

总体继续使用当前项目的暖白、近黑、低饱和中性色和深色模式能力。

需要收敛的点：

- 减少每个页面自己发明头部和卡片样式。
- 卡片圆角控制在 `8px-12px`，后台偏 `8px`，导航卡片可 `10px-12px`。
- 避免重阴影和大面积装饰背景，尤其后台页面应更克制。
- 公开首页可以稍微轻松，但仍以可读和快速访问为主。
- 统一按钮高度：普通按钮 `40px`，小按钮 `32px`，图标按钮 `40px`。

## 响应式策略

必须适配手机端：

- 公开首页。
- 登录页。
- 私有导航页。

不强制适配手机端：

- 后台管理。
- 复杂设备控制后台页。

手机端规则：

- 顶部操作可折行或收进菜单，不能横向溢出。
- 导航卡片从多列自动降到单列或两列。
- 搜索框始终在第一屏容易触达。
- 文本优先换行或省略，不能挤压按钮。

## 后续实施顺序建议
